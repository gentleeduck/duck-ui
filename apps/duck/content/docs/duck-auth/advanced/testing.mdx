## An engine for tests

```ts
import { createTest } from '@gentleduck/auth/test'
import { expect, it } from 'vitest'

it('signs in with the right password', async () => {
  const auth = createTest()
  const ada = await auth.identities.create({ profile: { username: 'ada', email: 'ada@example.com' } })
  await auth.passwords.set(ada.id, 'correct horse battery staple', auth.cfg.stores.credentials)

  const { sid, session } = await auth.flows.signIn({
    providerId: 'password',
    input: { email: 'ada@example.com', password: 'correct horse battery staple' },
  })

  expect(session?.identityId).toBe(ada.id)
  const resolved = await auth.resolveSession({ headers: new Headers({ authorization: `Bearer ${sid}` }) }).orNull()
  expect(resolved?.identity?.profile.email).toBe('ada@example.com')
})
```

`createTest()` is an engine over a `MemoryAdapter`, the bearer transport, a memory limiter allowing 1000 attempts a minute, and the password, MFA and API key providers. Each piece can be replaced:

```ts
import { MemoryLimiter } from '@gentleduck/auth/limiters/memory'

const auth = createTest({ limiter: new MemoryLimiter({ max: 2, windowMs: 60_000 }) })
// The third wrong password in a minute throws AUTH_RATE_LIMITED.
```

| Override | Replaces |
| --- | --- |
| `adapter`, `stores` | The memory adapter, or the whole store bag. |
| `transport`, `limiter`, `events` | Those engine pieces. |
| `providers` | Added after the three built in. |
| `passwords`, `mfa`, `apiKeys` | Those providers' options. |

`noopLimiter()` from `@gentleduck/auth/limiters/mock` never refuses, for a test that runs the same flow many times.

## Capturing what would be sent

```ts
import { MemoryAdapter } from '@gentleduck/auth/adapters/memory'
import { createAuth } from '@gentleduck/auth/core'
import { authTestDeliver } from '@gentleduck/auth/test'

const { deliver, outbox } = authTestDeliver()
const auth = createAuth({ baseUrl: 'https://app.example.com', stores: new MemoryAdapter(), deliver, strict: false })

const ada = await auth.identities.create({ profile: { username: 'ada', email: 'ada@example.com' } })
await auth.flows.requestEmailVerification({ identityId: ada.id })

expect(outbox[0]).toMatchObject({ kind: 'email-verification', identityId: ada.id })
const token = new URL(String(outbox[0]?.vars.url)).searchParams.get('token')
```

`outbox` holds every [message](/duck-auth/core/delivery) as `deliver` would have received it, with `identityId` and `tenantId` added.

## Redis

`fakeRedis()` from `@gentleduck/auth/test` is an in-memory client for the [`adapters/redis`](/duck-auth/adapters/redis) stores:

```ts
import { session } from '@gentleduck/auth/adapters/redis'
import { fakeRedis } from '@gentleduck/auth/test'

const sessions = session({ redis: fakeRedis() })
```

## The client

The client calls the `fetch` it is given, so a test can answer it directly:

```ts
import { createAuthClient } from '@gentleduck/auth/client/vanilla'

const client = createAuthClient({
  baseUrl: '/auth',
  fetch: async (url) =>
    String(url) === '/auth/session'
      ? Response.json({ session: null, identity: null })
      : Response.json({ ok: false, error: { code: 'AUTH_INVALID_CREDENTIALS', status: 401 } }, { status: 401 }),
})
```

For component stories, the [Storybook decorator](/duck-auth/client/react#storybook) renders against a mock client.
