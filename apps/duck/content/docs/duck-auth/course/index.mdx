This course builds the authentication for **DuckNotes**, a small notes app, one chapter at a time. Every chapter adds to the same source tree, and every snippet runs as shown against `@gentleduck/auth`.

## What you build

<MermaidDiagram chart={`flowchart LR
    B["Browser: sign-in form, notes page"] --> X["Express server"]
    X --> E["AuthEngine"]
    E --> ST["Stores: identities, credentials, sessions"]
    E --> M["deliver: your mailer"]
    X --> N["Notes API"]`} />

By the end, people sign up, verify their address, sign in with a password, a mailed link or GitHub, add a TOTP second factor, and must step up before a destructive action. It all runs on Postgres and Valkey behind a `strict()` production check.

## Prerequisites

- TypeScript and `async`/`await`.
- Node.js 22 or newer, or Bun.
- No database until chapter 8, which uses Postgres and Valkey.

## Setup

<Steps>

<Step>Create the project</Step>

```bash
mkdir ducknotes && cd ducknotes
npm init -y
npm pkg set type=module
mkdir src
```

<Step>Install duck-auth</Step>

<PackageManagerTabs bun="bun add @gentleduck/auth @node-rs/argon2" npm="npm i @gentleduck/auth @node-rs/argon2" pnpm="pnpm add @gentleduck/auth @node-rs/argon2" yarn="yarn add @gentleduck/auth @node-rs/argon2" />

`@node-rs/argon2` is the password hasher's peer. Everything else is installed by the chapter that needs it.

<Step>Add a runner</Step>

```bash
npm i -D tsx
npx tsx src/main.ts
```

<Step>Start</Step>

Go to [Chapter 1: your first sign-in](/duck-auth/course/chapter-1).

</Steps>

## How the chapters are written

Each chapter has **learning goals**, a **diagram** of what it introduces, the **code**, **what just happened** inside the engine, and a **try it** exercise. New concepts link to their reference page.

<Callout tone="info" title="Version">
The code is verified against `@gentleduck/auth` 5.13.0. Import paths come from the package `exports` map: `@gentleduck/auth/core`, `@gentleduck/auth/adapters/memory`, `@gentleduck/auth/server/express` and so on.
</Callout>
