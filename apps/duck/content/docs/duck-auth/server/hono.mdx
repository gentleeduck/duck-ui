```ts
import { mountHono } from '@gentleduck/auth/server/hono'
import { type Context, Hono } from 'hono'
import { getConnInfo } from 'hono/bun'

const app = new Hono()
mountHono<Context>(app, auth, { ip: (c) => getConnInfo(c).remote.address })

export default app
```

Hono resolves no client IP, so `ip` is how the session learns one. Use the `getConnInfo` for your runtime, or read the header your proxy sets if you trust it. Without `ip`, sessions record none.

## Routes

`mountHono` mounts the [shared routes](/duck-auth/server#the-routes) under `/auth` (`prefix` moves them), and these groups, each dropped by naming it in `skip`:

| Group | Routes |
| --- | --- |
| `oauth` | `GET`, `POST /auth/providers/:id/callback` |
| `magic-link` | `GET /auth/magic-link/verify?token=` |
| `passkey` | `POST /auth/passkey/begin`, `POST /auth/passkey/complete` |
| `totp` | `POST /auth/mfa/totp/begin`, `confirm`, `verify` and `remove`, and `POST /auth/mfa/backup-codes/regenerate` |

```ts
mountHono(app, auth, { prefix: '/api/auth', skip: ['passkey', 'totp'] })
```

- The magic-link provider's links point to `/auth/magic-link/callback` by default. Pass `callbackPath: '/auth/magic-link/verify'` to [`magicLink`](/duck-auth/providers/magic-link) so they land on this route.
- The MFA routes act on the signed-in identity. Removing TOTP and regenerating backup codes need a session at AAL 2, and answer `AUTH_STEP_UP_REQUIRED` otherwise. See [MFA](/duck-auth/guides/mfa).
- The OAuth callback answers the session cookies and an empty 200. To land the browser on a page, skip `oauth` and write the callback yourself, as on the [OAuth page](/duck-auth/providers/oauth#the-routes).
- CORS is yours to mount, with `hono/cors`.

## Your own routes

```ts
import { honoActorContext, honoCsrf } from '@gentleduck/auth/server/hono'

app.use('/api/*', honoCsrf(auth), honoActorContext(auth))

app.get('/api/me', async (c) => {
  const resolved = await auth.resolveSession({ headers: c.req.raw.headers }).orNull()
  if (!resolved) return c.json({ error: 'unauthenticated' }, 401)
  return c.json(resolved.identity)
})
```

`honoActorContext` answers a refusal itself, since Hono's default error handler turns any throw into a 500. `honoCaller({ ip, req: c.req })` is the IP and User-Agent to pass to a flow you call yourself.

For a layout `mountHono` does not fit, mount the single-route handlers `honoSignIn`, `honoSignOut`, `honoSession` and `honoProviderBegin` over `toHonoAdapterCtx`:

```ts
import { honoSignIn, toHonoAdapterCtx } from '@gentleduck/auth/server/hono'

app.post('/login', (c) => honoSignIn(auth)(toHonoAdapterCtx(c)))
```
