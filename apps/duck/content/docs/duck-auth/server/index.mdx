Each adapter turns the engine's flows into handlers for one framework. None imports its framework: each is typed against the few methods it calls.

## The routes

| Route | Does |
| --- | --- |
| `POST /auth/signin` | Signs in with a `{ providerId, input }` body. |
| `POST /auth/signout` | Revokes the session the request carries. |
| `GET /auth/session` | Answers `{ session, identity }`, both `null` when signed out. |
| `POST /auth/providers/:id/begin` | Starts a provider's flow: the OAuth redirect, the magic-link email, the passkey challenge. |
| `GET` and `POST /auth/providers/:id/callback` | Where an OAuth IdP sends the browser back. |

These are the paths the [client](/duck-auth/client) calls under its `baseUrl`, `/auth` by default. Mount only what you use; a password-only app needs the first three.

## What every handler does

- Checks CSRF on each POST, answering 403 `AUTH_CSRF` on a failure. A cross-site `Sec-Fetch-Site` is refused, and once a session exists, the `x-csrf-token` header must match its [CSRF cookie](/duck-auth/core/transports/cookie#the-csrf-cookie). A bearer request with no cookie skips the token.
- Stamps the session with the caller's User-Agent and the IP the framework resolved, never a forwarded header. Set your framework's proxy trust so that IP is the client's.
- Answers `Cache-Control: no-store`.
- Answers an `AuthError` as `{ ok: false, error: { code, status, detail? } }` at its status. Anything else is a 500 with the cause logged and withheld.
- Refuses a redirect to anything but a same-origin path or an http(s) URL.

The OAuth callback is the exception to CSRF: Apple posts it from its own page, and the signed `state` bound to the pre-auth cookie is the proof instead. It drives only `oauth` providers, so it signs nobody in any other way.

## Your own routes

For a route you write:

- **Read the session** with `auth.resolveSession({ headers })`. `.orNull()` answers `null` when there is none, and still throws when the store is down.
- **Guard it against CSRF** with the adapter's CSRF helper, on every state-changing route a cookie session reaches.
- **Pass the caller** to a flow you call yourself, with the adapter's caller helper: `expressCaller(req)`, `honoCaller(c)`, and so on.
- **Bind the actor** with the adapter's actor scope, so writes downstream record who made them in `created_by` and `updated_by`. Give it `getCaller`, and it also runs [hijack detection](/duck-auth/core/sessions#hijack-detection) and the [anomaly detectors](/duck-auth/core/anomaly) on every request.

The actor scope authorises nothing: it binds nobody for a request with no session, and refusing that is your guard's job.
