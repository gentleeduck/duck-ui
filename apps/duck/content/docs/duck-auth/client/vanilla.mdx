```ts
import { createAuthClient } from '@gentleduck/auth/client/vanilla'

type Profile = { username: string; email: string; displayName?: string }

export const client = createAuthClient<Profile>({ baseUrl: '/auth' })
```

| Option | Default | Does |
| --- | --- | --- |
| `baseUrl` | `/auth` | Where the server mounted the routes. |
| `fetch` | `globalThis.fetch` | The fetch to call through, for a test stub or a retry wrapper. |
| `headers` | none | Sent with every request, such as a tenant header. |
| `csrfCookieName` | `__Host-duck-csrf` | The cookie the CSRF token is read from. `duck-csrf` on http; see [matching the server](/duck-auth/client#matching-the-server). |
| `csrfHeaderName` | `x-csrf-token` | The header the token is sent on. |
| `notifyImmediately` | `true` | Whether `onChange` replays the current state to a new listener. |

## Methods

Each answers an [envelope](/duck-auth/client#what-a-call-answers).

| Method | Calls | Answers |
| --- | --- | --- |
| `signIn({ providerId, input })` | `POST /signin`, then `GET /session` | The new session and identity. |
| `signOut()` | `POST /signout` | `data: null`. The local state clears even when the server refuses. |
| `getSession()`, `refresh()` | `GET /session` | `{ session, identity }`, both `null` for a guest. |
| `beginProvider(id, input)` | `POST /providers/:id/begin` | What the provider's begin answers. An OAuth or SAML begin answers `{ url }`, and the page goes there. |
| `signUp(input, { path })` | `POST {path}`, under `baseUrl`, `/signup` by default | Your route's body. No adapter mounts a sign-up route; point `path` at yours. |
| `onChange(listener)` | | Returns an unsubscribe. |

```ts
const off = client.onChange(({ identity }) => {
  document.body.dataset.authed = identity ? 'true' : 'false'
})
await client.getSession()
```

The listener runs after each session read, sign-in and sign-out. Before the first read the client holds no state, so a new listener hears nothing until one lands.

## Provider flows

```ts
// Emails a sign-in link.
await client.beginProvider('magic-link', { email })

// Sends the page to Google.
await client.beginProvider('oauth:google')
```

A passkey sign-in takes the options `begin` answers and signs in with the browser's response; the [passkey page](/duck-auth/providers/passkey) has the whole exchange.

## On the server

A server reads the session from the engine, not through this client: `auth.resolveSession(req)`, as the [Next.js page](/duck-auth/server/next#reading-the-session) does.
