## Quick comparison

| | @gentleduck/primitives | Radix UI Primitives |
|---|---|---|
| **API compatibility** | Same compound-component pattern | Original API |
| **Packaging** | One package, `@gentleduck/primitives`, a subpath per primitive | One package per primitive |
| **Styled layer** | `npx gentleduck add` copies the styled components into your project | shadcn copies its own into your project |
| **Bundle** | Tree-shakable ESM, built with tsdown | Tree-shakable ESM |
| **Calendar primitive** | Included (Calendar.Root, Calendar.Grid, Calendar.Day) | Not available |
| **asChild** | Supported via Slot | Supported via Slot |
| **data-state attributes** | Same pattern (`data-state="open"`, `data-state="closed"`) | Same pattern |
| **ARIA** | WAI-ARIA compliant | WAI-ARIA compliant |
| **Animation** | Presence primitive + `@gentleduck/motion` tokens | Presence primitive |
| **Direction** | Direction primitive (LTR/RTL) | Direction primitive (LTR/RTL) |
| **Framework** | React 18+ | React 18+ |

## What's the same

`@gentleduck/primitives` follows the same patterns as Radix UI. If you know Radix, you know gentleduck primitives.

### Compound components

Both use the Root / Trigger / Content pattern:

```tsx
// Radix UI
import * as Dialog from '@radix-ui/react-dialog'

<Dialog.Root>
  <Dialog.Trigger>Open</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Overlay />
    <Dialog.Content>
      <Dialog.Title>Title</Dialog.Title>
    </Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>

// gentleduck primitives
import * as Dialog from '@gentleduck/primitives/dialog'

<Dialog.Root>
  <Dialog.Trigger>Open</Dialog.Trigger>
  <Dialog.Portal>
    <Dialog.Overlay />
    <Dialog.Content>
      <Dialog.Title>Title</Dialog.Title>
    </Dialog.Content>
  </Dialog.Portal>
</Dialog.Root>
```

### asChild pattern

Both support `asChild` via the Slot primitive to merge props onto a child element instead of rendering a wrapper:

```tsx
<Dialog.Trigger asChild>
  <button className="custom-trigger">Open</button>
</Dialog.Trigger>
```

### data-state attributes

Both expose component state through `data-*` attributes for CSS targeting:

```css
[data-state='open'] { opacity: 1; }
[data-state='closed'] { opacity: 0; }
```

### ARIA compliance

Both implement WAI-ARIA authoring practices. Dialog manages focus trapping, escape dismissal, and `aria-labelledby` / `aria-describedby`. Menus implement `role="menu"` with roving tabindex. Select implements `role="listbox"`.

## What's different

### Where behaviour differs

Both are dependencies you install. The styled components built on gentleduck's primitives are copied into your project by `npx gentleduck add`, as shadcn copies its Radix-based ones, so the layer you style is yours either way. Each primitive's [API page](/duck-primitives/api) says where it behaves differently from Radix, and its README in the repository lists every fix and the test that proves it.

### Calendar primitive

`@gentleduck/primitives/calendar` provides accessible Calendar.Root / Calendar.Grid / Calendar.Day compound components backed by the `@gentleduck/calendar` engine. Radix does not ship a calendar primitive.

### Animation integration

Radix provides a Presence primitive for mount/unmount animations. gentleduck extends this with two improvements:

1. **Exit animations** - Presence waits on the `finished` promise of every CSS animation the content runs as it closes, read from `element.getAnimations()`. An exit with several animations waits for the last, an exit that interrupts an opening animation runs to its end, and an exit animation with no `@keyframes`, or one cancelled in its first frame, unmounts the content at once. Radix waits for `animationend` and `animationcancel` events matched by name, so the first of several animations ends the exit, Firefox's late cancel of the opening animation can end it at once, and content whose exit has no keyframes stays in the page.

2. **Motion tokens** - `@gentleduck/motion` provides prebuilt keyframe sets and reduced-motion utilities that integrate with the Presence lifecycle. Animations automatically respect `prefers-reduced-motion`.

### Tooltip improvements

gentleduck's Tooltip adds `disableCloseOnClick` on the trigger. In Radix, wrapping an interactive element (like a Toggle button) in a TooltipTrigger causes the tooltip to intercept the click and close instead of letting the toggle work. gentleduck solves this at the primitive level with one prop. It also takes `closeDelay` and `disabled`, a press during the open delay drops the open, and a trigger nested in another opens only its own tooltip.

### What else it adds

- **Accordion**: `onOpenChange` on each item, `hiddenUntilFound` for the browser's find-in-page, `Header` and `Indicator` parts, and `disabled`, `loop` and `onFocusChange` on the root.
- **Dialog, Alert Dialog and Sheet**: nested dialogs with `data-nested` and a stacking variable, `initialFocus` and `finalFocus`, and a ref as the portal's `container`.
- **Popover**: `initialFocus`, `finalFocus`, and `Title` and `Description` parts that name and describe the content.
- **Menus**: `closeOnSelect` on an item and `closeParentOnEsc` on a submenu; a controlled `open` on Context Menu; `orientation`, `disabled` and `modal` on Menubar.
- **Select**: `multiple`, `items` as data, a function child on `Value`, an empty item `value` that clears, and `PageUp` and `PageDown`.
- **Radio Group**: `readOnly`, `form`, and `aria-disabled` on a disabled group.
- **Slider**: `largeStep`, `Slider.Value`, `preserveThumbOrder`, and `index` so a range renders its thumbs on the server.
- **Toggle and Toggle Group**: children as a function of the pressed state, and `deselectable={false}` for a segmented control.
- **Progress**: `Label`, `Value` and `min`.
- **Navigation Menu**: `activationMode`, `closeDelay`, and `closeOnSelect` on a link.
- **Avatar**: the image in the server's HTML, so it downloads before hydration, and `delayMs={0}` shown in the first render.
- **Popper**: physical sides mirror in right to left, `shiftCrossAxis`, `anchor` and `updateOnScroll`.

### Bundled together

Radix ships each primitive as a separate npm package (`@radix-ui/react-dialog`, `@radix-ui/react-popover`, etc.), built on shared internal packages such as react-slot, react-primitive and react-dismissable-layer. A bundler includes each of those once only while every primitive asks for the same version of it.

gentleduck ships all primitives from a single package, so Slot, Presence, Popper, focus scope and the dismissable layer are one copy whatever you install. Every additional primitive adds only its own code.

### Bundle size

Both libraries go through the same build: an entry re-exporting the component, bundled and minified by esbuild with React external, then gzipped.

## Migration

For most primitives, migration is a namespace change.

### 1. Update imports

```diff
- import * as Dialog from '@radix-ui/react-dialog'
+ import * as Dialog from '@gentleduck/primitives/dialog'

- import * as Popover from '@radix-ui/react-popover'
+ import * as Popover from '@gentleduck/primitives/popover'

- import * as DropdownMenu from '@radix-ui/react-dropdown-menu'
+ import * as DropdownMenu from '@gentleduck/primitives/dropdown-menu'
```

### 2. Remove Radix packages

```bash
npm uninstall @radix-ui/react-dialog @radix-ui/react-popover @radix-ui/react-dropdown-menu
# ... and all other @radix-ui/* packages
```

### 3. Install gentleduck primitives

```bash
npm install @gentleduck/primitives
```

### 4. Verify behavior

The component API, data attributes, and ARIA patterns are the same. Run your tests. The main things to check:

- **Custom `asChild` usage**: Same API, should work identically.
- **CSS selectors targeting `data-state`**: Same attribute values.
- **Animation classes**: If you used Radix's `data-state` for CSS transitions, they still work. If you want motion tokens, add `@gentleduck/motion`.
- **TypeScript types**: Prop types match. Generic patterns are the same.

Where gentleduck behaves differently, check these:

- `DirectionProvider` renders a `div` with `display: contents`, so a child selector across it, such as `.list > li`, no longer matches. `useDirection` reads `<html dir>` without a provider, where Radix answers `ltr`.
- `Arrow` draws a rounded tip, and its `asChild` draws your children inside its own svg, where Radix slots onto a child that has to be the whole svg.
- `Avatar.Image` is in the DOM, hidden, while it loads and after it fails. Check `[data-state="loaded"]` rather than its presence.
- `ToggleGroup.Root` is a `radiogroup` when single and a `toolbar` when multiple, where Radix's is a `group`. Pass `role="group"` to keep it.
- A right click on an open context menu closes it, where Radix opens it again at the pointer.
- `Menubar.Content` takes no `trapFocus`, `disableOutsidePointerEvents` or `disableOutsideScroll`; the root's `modal` decides them for every menu.
- `Select` dispatches a `change` that does not bubble when its `value` prop changes, so a form's `onChange` hears only the user's picks.
- `RadioGroup`'s `onValueChange` is typed `string | null`, since a form reset back to no pick calls it with `null`, as Radix's does.
- `Slot` never passes `dangerouslySetInnerHTML` on, and given two `Slottable`s it lands on the first, where Radix lands on the last.
- Where the browser has no `element.getAnimations()`, as in jsdom, `Presence` unmounts content at once, so a test that fired `animationend` stubs `getAnimations` instead.
- `DismissableLayer` dispatches no `dismissableLayer.update` event.

## Why teams switch to gentleduck primitives

You get the same API with less code. The Dialog, Popover, Select, and Tooltip work identically to their Radix equivalents - same compound pattern, same data-state attributes, same ARIA behavior. Migration is a namespace change in your imports.

You get a smaller bundle for most primitives both libraries ship. A Radio Group is 7.3 KB against 10.1 KB and a Slider 6.6 KB against 9.5 KB. A Dialog is 13.7 KB against 13.4 KB, with nested dialogs and focus targets Radix does not have.

You get primitives Radix does not ship. Calendar with 4 calendar systems, Command for command palettes, Sheet, and Pagination are built-in, and Input OTP is stable where Radix's is a preview. With Radix, these require separate third-party libraries.

You get the edge cases fixed. Focus trapping inside iframes and shadow roots, dismiss behaviour for nested overlays and scrollbars, exit animations that finish, and forms that reset: each is listed, with its test, in the primitive's README.

**Why some teams stay on Radix:**
- They prefer an externally maintained dependency over owning the source
- They need per-primitive package installs for strict dependency auditing
